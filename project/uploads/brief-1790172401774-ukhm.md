# Brief de refonte — interface du studio de montage

> **À lire en entier avant de toucher au CSS.** Ce document contient tout ce qu'il
> faut pour refaire l'interface sans casser l'application : la structure réelle,
> les données affichées, et surtout le **contrat DOM** dont dépend le JavaScript.

---

## 1. Ce qu'est le produit

Un **studio de montage vidéo local**, pour produire des documentaires YouTube en
français (type enquête / décryptage économique). Il tourne entièrement sur le Mac
de l'utilisateur, sans cloud.

Le moteur découpe un script en plans, les cale sur la voix off, applique une charte
graphique, et rend un MP4. **L'interface web sert à relire et corriger** ce montage
automatique avant le rendu final.

**Le geste central à optimiser :** relire l'épisode plan par plan et corriger 5 à
15 plans en quelques minutes. Tout le reste est secondaire.

Objectif de l'utilisateur : produire un épisode de 10-20 minutes en 30-45 minutes
de travail humain.

### Utilisateur

Une seule personne, sur son Mac, souvent le soir. Pas d'équipe, pas de
collaboration, pas de comptes. Elle connaît le montage vidéo mais n'est pas
développeuse.

## 2. Direction artistique demandée

### Palette imposée

| Rôle | Code |
|---|---|
| Fond principal | `#0D0D0F` |
| Surface | `#151518` |
| Surface secondaire | `#1C1C21` |
| Jaune (accent) | `#FFC72C` |
| Rouge (alertes uniquement) | `#DA291C` |
| Texte principal | `#F5F5F5` |
| Texte secondaire | gris clair |

**Le jaune est un accent, pas une couleur dominante.** Le rouge est réservé aux
alertes, conflits et informations sensibles.

### Intentions

Beaucoup d'espace · typographie très propre · micro-animations · hover states ·
transitions rapides · cartes élégantes · coins légèrement arrondis · bordures très
discrètes · hiérarchie visuelle forte.

**L'interface doit donner l'impression d'un outil professionnel de post-production.**

### Références d'ambiance

Logiciels créatifs pro, interfaces de newsroom, outils de post-production modernes,
Linear, Raycast, Arc, Framer, interfaces Apple pro, dashboards éditoriaux premium.

⚠️ **Ne copie aucun de ces produits.** Il faut une identité propre.

### À éviter absolument

- la sensation de « dashboard SaaS générique »
- les aplats de jaune décoratifs
- les ombres portées partout
- les polices génériques (Inter, Roboto, system-ui par défaut) sans intention
- les dégradés violets

## 3. Mon autocritique de la version actuelle

L'utilisateur a jugé le résultat « pas ouf ». Voici où je pense que ça pèche, pour
éviter de refaire les mêmes erreurs :

1. **Trop timide.** Tout est gris sur gris, sans vrai point focal. Rien n'attire
   l'œil vers le lecteur, qui est pourtant le cœur de l'écran.
2. **Hiérarchie faible.** La barre du haut, la timeline et l'inspecteur ont des
   poids visuels comparables. On ne sait pas où regarder.
3. **Pas d'identité.** C'est « correct et sombre », mais ça ne ressemble à rien
   en particulier. Aucun parti pris typographique ou structurel mémorable.
4. **Densité mal dosée.** Beaucoup d'espace perdu autour du lecteur, alors que
   l'inspecteur est tassé sur une seule ligne de champs.
5. **Cartes de plan fades.** Elles portent l'essentiel de l'information
   (vignette, durée, recette, phrase, état) mais ne la hiérarchisent pas.
6. **Le lecteur ne fait pas « player ».** Il manque le vocabulaire visuel d'un
   outil vidéo : repères temporels, marqueurs, sensation de piste.

Pistes non exploitées : l'esthétique de la **table de montage** (bandes de film,
timecodes, marqueurs de chapitre), le **grain éditorial** (filets, capitales
espacées, numérotation typographique), un vrai **contraste de densité** entre zone
de lecture (calme, aérée) et zone de travail (dense, technique).

## 5. Les données réellement affichées

### Un épisode

```json
{
  "nom": "episode-test",
  "titre": "Épisode de test",
  "duree_voix": 26.71,
  "duree_totale": 28.71,
  "plans_desactives": [],
  "recettes": ["accroche_choc", "carte_flux", "carton_chapitre", "chiffre_cle",
               "document_surligne", "image_ambiance", "revelation",
               "texte_plein_ecran", "ticket_de_caisse"],
  "couleurs": { "fond": "#121212", "jaune": "#FFC72C", "rouge": "#DA291C" }
}
```

### Un plan (l'objet central de l'interface)

```json
{
  "index": 0,
  "origine": 0,
  "numero": 1,
  "debut": 0.0,
  "fin": 4.5,
  "duree": 4.5,
  "recette": "accroche_choc",
  "texte": "[2 MILLIONS] PAR JOUR",
  "visuel": "visuels/ville.mp4",
  "source": "",
  "phrase": "chaque jour en France, des millions de personnes passent une porte,",
  "fond_uni": false,
  "etat": "ok",
  "corrige": false
}
```

Points à traiter visuellement :

- **`etat`** vaut `"ok"`, `"attention"` ou `"bloquant"` → 🟢 🟠 🔴.
  C'est l'indicateur qualité du plan. Doit se lire d'un coup d'œil sur la carte
  **et** sur le segment de piste.
- **`texte`** : les mots entre `[crochets]` s'affichent **en jaune**, le reste en
  blanc. C'est une règle de la charte vidéo, à refléter dans l'aperçu.
- **`corrige`** : le plan a été modifié par l'utilisateur → mériterait un marqueur
  discret mais repérable.
- **`duree`** : la charte impose 1,5-2,5 s à l'accroche et 2,5-4 s ensuite. Un plan
  trop long est signalé par `etat`.
- **`phrase`** : les mots réellement prononcés pendant le plan (issus de la
  transcription). Longueur très variable, souvent tronquée.

Un épisode réel compte **50 à 80 plans**. La timeline doit rester lisible et fluide
à cette échelle — c'est le vrai test.

### Les médias

Groupés par rôle : `voix`, `visuel`, `graphique`, `document`, `carton`, `musique`.

```json
{ "chemin": "visuels/foule.jpg", "nom": "foule.jpg",
  "nature": "image", "taille": "97 Ko" }
```

`nature` ∈ `image` · `video` · `audio`.

### Le contrôle qualité

```json
{ "resume": { "bloquant": 0, "attention": 3, "total": 3 },
  "problemes": [
    { "niveau": "attention",
      "titre": "Plan 7 : image fixe sans mouvement",
      "detail": "Une image sans zoom paraît figée à l'écran.",
      "correction": "Ajoute « zoom: 0.06 » à ce plan.",
      "plan": 6 }
  ] }
```

Cliquer un problème saute au plan concerné.

import, rendu) cible ces éléments **par identifiant**. Tu peux refaire tout le

### Attributs `data-` pilotés par le JS

| Attribut | Valeurs | Porté par |
|---|---|---|
| `data-etat` | `ok` · `attention` · `bloquant` | `.carte`, `.segment`, `.pastille` |
| `data-choisi` | `oui` · `non` | `.carte` |
| `data-actif` | `oui` · `non` | `.segment` |
| `data-index` | numéro du plan | `.carte`, `.segment` |
| `data-ouvert` | `oui` · `non` | `.medias__groupe` (repli) |
| `data-survol` | `oui` · `non` | `#zone-depot` (glisser-déposer) |
| `data-niveau` | `bloquant` · `attention` · `ok` | `.probleme`, `.qc__chiffre` |
| `data-type` | `info` · `succes` · `erreur` | `#alerte` |
| `data-fermer` | id à masquer | boutons de fermeture |

### Piège à connaître

```css
[hidden] { display: none !important; }
```

**Garde cette règle.** Le JS masque les panneaux avec `element.hidden = true`.
Sans elle, toute classe qui fixe `display` (grid, flex…) l'emporte sur le
navigateur et les voiles ne se ferment plus. C'est le bug qui vient d'être
corrigé.

## 7. Contraintes techniques

- **HTML + CSS + JavaScript natifs.** Pas de React, Vue, Svelte, ni build step.
  Pas de framework CSS (pas de Tailwind, Bootstrap…). C'est une exigence du
  projet : l'outil doit rester simple à lancer et à maintenir.
- **Pas de dépendance réseau.** Ni CDN, ni Google Fonts : l'application doit
  fonctionner hors ligne. Une police personnalisée doit être **embarquée** dans
  `frontend/` et déclarée en `@font-face`.
- Trois fichiers : `frontend/index.html`, `frontend/style.css`, `frontend/app.js`,
  servis par FastAPI (`app.py`). `/style.css` et `/app.js` sont servis à la racine.
- Cible : **Safari et Chrome récents sur macOS**, écran 1440 × 900 minimum.
  Pas de support mobile requis, mais l'écran ne doit pas casser sous 1200 px.
- Respecter `prefers-reduced-motion`.
- Les textes de l'interface sont **en français**.

## 8. Essayer l'application

```bash
cd ~/Projects/montage-auto
./start.sh
```

Le navigateur s'ouvre sur un épisode de démonstration (10 plans, ~29 s) avec de
vrais médias et une vraie voix off. Appuyer sur **Espace** lance l'aperçu
interactif : la voix se joue et les vignettes défilent.

Si le dossier `episode-test/` est absent :

```bash
.venv/bin/python3 scripts/creer_medias_test.py
```

Raccourcis : `Espace` lecture · `←` `→` plan précédent/suivant · `Échap` ferme
les panneaux.

### Vérifier qu'on n'a rien cassé

```bash
.venv/bin/python3 - <<'PY'
import re, pathlib
html = pathlib.Path("frontend/index.html").read_text(encoding="utf-8")
js   = pathlib.Path("frontend/app.js").read_text(encoding="utf-8")
manquants = sorted(set(re.findall(r'\$\("([^"]+)"\)', js)) - set(re.findall(r'id="([^"]+)"', html)))
print("Identifiants manquants dans le HTML :", manquants or "aucun ✓")
PY
```

Ce contrôle doit afficher « aucun ». Il attrape l'erreur la plus coûteuse d'une
refonte : un `id` perdu en route.

## 9. Ce qui fonctionne déjà — à ne pas casser

- aperçu interactif : voix off jouée dans le navigateur, vignettes synchronisées,
  aucun rendu nécessaire
- corrections plan par plan, écrites dans un fichier séparé (`corrections.yaml`) :
  le `projet.yaml` de l'utilisateur n'est jamais modifié
- import par glisser-déposer, rangement automatique par type
- rendu aperçu 540p et master 1080p, avec progression par phase réelle
- contrôle qualité cliquable, qui saute au plan concerné
- raccourcis clavier

Le back-end est stable et testé (53 tests). **La refonte ne devrait toucher que
`index.html` et `style.css`**, et `app.js` uniquement si la structure DOM change.

async function api(chemin, options = {}) {
  const reponse = await fetch(chemin, options);

function signaler(message, type = "info") {
  const boite = $("alerte");

  boite.hidden = false;

/* ---------------------------------------------------------------- formats */
function chrono(secondes) {
  if (!isFinite(secondes) || secondes < 0) secondes = 0;
  const m = Math.floor(secondes / 60);
  const s = Math.floor(secondes % 60);
  return `${m}:${String(s).padStart(2, "0")}`;
}

function echapper(texte) {
  const d = document.createElement("div");
  d.textContent = texte;
  return d.innerHTML;
}

/** « gagne [BEAUCOUP] plus » → « gagne <b>BEAUCOUP</b> plus » */
function texteEnrichi(texte) {
  return echapper(texte)
    .replace(/\[([^\]]*)\]/g, "<b>$1</b>")
    .replace(/\\n|\n/g, "<br>");
}

function choisirPlan(index, deplacerLecture) {
  if (!etat.donnees || !etat.donnees.plans.length) return;
  index = Math.max(0, Math.min(index, etat.donnees.plans.length - 1));
  etat.choisi = index;

  document.querySelectorAll(".carte").forEach((c) => {
    c.dataset.choisi = Number(c.dataset.index) === index ? "oui" : "non";
  });
  const carte = document.querySelector(`.carte[data-index="${index}"]`);
  if (carte) carte.scrollIntoView({ block: "nearest", inline: "center" });

  remplirInspecteur(etat.donnees.plans[index]);

  if (deplacerLecture) {
    const plan = etat.donnees.plans[index];
    if (isFinite(audio.duration)) {
      audio.currentTime = Math.min(plan.debut + 0.02, audio.duration - 0.05);
    }
    afficherPlan(index);
    majPosition();
  }
}

/* ---------------------------------------------------------------- lecteur */
function planAuTemps(t) {
  const plans = etat.donnees.plans;
  for (let i = plans.length - 1; i >= 0; i--) {
    if (t >= plans[i].debut) return i;
  }
  return 0;
}

function afficherPlan(index) {
  if (index === etat.courant || !etat.donnees) return;
  etat.courant = index;
  const plan = etat.donnees.plans[index];
  if (!plan) return;

  const img = $("image-plan");
  img.src = `/api/episode/${encodeURIComponent(etat.episode)}/vignette/${index}`;

  $("badge-plan").textContent =
    `PLAN ${String(plan.numero).padStart(2, "0")} · ${plan.recette}`;

    zone.innerHTML = `<p class="incrustation__texte">${texteEnrichi(plan.texte)}</p>`;
  } else {
    zone.innerHTML = "";
  }

  document.querySelectorAll(".segment").forEach((s) => {
    s.dataset.actif = Number(s.dataset.index) === index ? "oui" : "non";
  });
}

async function corriger(modifications) {
  const plan = etat.donnees.plans[etat.choisi];
  if (!plan) return;
  const memoire = etat.choisi;
  try {
    etat.donnees = await api(
      `/api/episode/${encodeURIComponent(etat.episode)}/plan/${plan.origine}`,
      { method: "PATCH", headers: { "Content-Type": "application/json" },
        body: JSON.stringify(modifications) });
  } catch (e) {
    signaler(e.message, "erreur");
    return;
  }
  etat.courant = -1;
  dessinerTout();
  choisirPlan(Math.min(memoire, etat.donnees.plans.length - 1), false);
  afficherPlan(planAuTemps(audio.currentTime || 0));
  signaler("Correction enregistrée.", "succes");
}

      el.addEventListener("click", () => { fermer("tiroir-qc"); choisirPlan(p.plan, true); });
    }
    liste.appendChild(el);
  });
}

async function lancerRendu(qualite) {
  if (!etat.episode) return;
  const bloquants = etat.donnees.qc.resume.bloquant;
  if (qualite === "master" && bloquants) {
    if (!confirm(`${bloquants} problème(s) bloquant(s) sont signalés.\n\nRendre quand même le master ?`)) {
      ouvrir("tiroir-qc");
      return;
    }
  }
  $("lien-sortie").hidden = true;
  $("rendu-titre").textContent = qualite === "master" ? "Rendu du master 1080p" : "Aperçu 540p";
  $("rendu-journal").textContent = "";
  ouvrir("voile-rendu");
  try {
    await api(`/api/episode/${encodeURIComponent(etat.episode)}/rendu`, {
      method: "POST", headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ qualite }),
    });
    suivreRendu(qualite);
  } catch (e) {
    signaler(e.message, "erreur");
    fermer("voile-rendu");
  }
}

function suivreRendu(qualite) {
  clearInterval(etat.suiviRendu);
  etat.suiviRendu = setInterval(async () => {
    let s;
    try {
      s = await api(`/api/episode/${encodeURIComponent(etat.episode)}/rendu`);
    } catch (_) { return; }

    $("rendu-message").textContent = s.message || "";
    $("rendu-jauge").style.width = `${s.pourcent || 0}%`;
    $("rendu-pourcent").textContent = `${s.pourcent || 0} %`;
    $("rendu-restant").textContent = s.restant !== null && s.restant !== undefined && s.etat === "en_cours"
      ? `encore ~${chrono(s.restant)}` : "";
    $("rendu-journal").textContent = (s.journal || []).join("\n");

    if (s.etat === "termine") {
      clearInterval(etat.suiviRendu);
      $("rendu-message").textContent = "Terminé.";
      $("rendu-jauge").style.width = "100%";
      $("rendu-pourcent").textContent = "100 %";
      const lien = $("lien-sortie");
      lien.href = `/api/episode/${encodeURIComponent(etat.episode)}/sortie?qualite=${qualite}&t=${Date.now()}`;
      lien.hidden = false;
      signaler("Rendu terminé.", "succes");
    } else if (s.etat === "echec") {
      clearInterval(etat.suiviRendu);
      $("rendu-message").textContent = "Le rendu a échoué.";
      $("rendu-journal").textContent = s.erreur || "";
    }
  }, 900);
}
